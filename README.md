# tmus

Терминальный музыкальный плеер: демон `tmusd` + клиент `tmus`.
Воспроизведение — через `mpv`, каталог — через провайдеров, интеграция с
оболочкой — через MPRIS и иконку в трее.

Чем это отличается от очередного Electron-плеера:

- **свой клиент, а не обёрнутый браузер.** Замерено на одной машине,
  один и тот же трек: `ytmdesktop` — **11 процессов, 1329 МБ RSS**;
  `tmus` — **2 процесса, 52 МБ PSS**;
- **InnerTube напрямую**: каталог YouTube Music читается тем же
  протоколом, что и веб-клиент, без промежуточных сервисов;
- **офлайн-кэш**: играемый и следующий треки лежат на диске, сеть
  нужна один раз;
- **панель noctalia**: полная альтернатива TUI с vim-биндами, живёт
  в баре рабочего стола;
- vim-бинды везде — в панели и в TUI.

## Установка и запуск

Три шага. Копировать cookie из DevTools не нужно — плеер сам находит
сессию в профиле браузера.

```sh
cargo install --path crates/tmus-tui
cargo install --path crates/tmus-daemon
install -Dm644 packaging/tmusd.service ~/.config/systemd/user/tmusd.service
systemctl --user enable --now tmusd
```

Нужны `mpv` и `yt-dlp` в системе. Дальше — `tmus`.

Плагин noctalia — отдельный шаг: каталог
`packaging/noctalia/tmus` устанавливается в локальный каталог плагинов
noctalia (манифест объявляет `plugin_api = 24`). После включения плагина
в баре появляется виджет `q/tmus:tmus-widget`, панель и фоновый сервис
`watch`, который держит соединение с демоном и раздаёт состояние панели.

## Панель noctalia

Панель — модальное окно над рабочим столом: пока она открыта, она
захватывает весь алфавит, а ввод поиска ведёт сама (см. «Грабли» ниже —
почему ввод не через `ui.input`). Панель — модель буферов, как в нормальном
редакторе: центральная колонка (вид) — буфер 2, правая колонка — постоянная
интерактивная очередь — буфер 3. Видов пять, переключение без потери позиции:

| Секция | Цифра | Что показывает |
|---|---|---|
| Home | 1 | хиро играющего трека + полки рекомендаций |
| Search | 2 | поиск по трекам/артистам/плейлистам (вид «Collections») |
| Library | 3 | лайки, альбомы, плейлисты (сетка карточек); по умолчанию агрегирует всех подключённых клиентов |
| Clients | 4 | подключённые потребители демона |
| Equalizer | 5 | 10 полос и пресеты |

Отдельного вида «Queue» больше нет: очередь всегда справа, в любом виде.
У неё собственный курсор и follow-playing автоскролл за играющим треком
(ручной ход его выключает, Return на строке — включает снова), счётчик
`N/M` в заголовке и Enter = прыжок на позицию (`queue-goto`).

Нижний блок now-playing общий для всех видов: арт, трек, кнопки
транспорта и прогресс, а в основании — полоса спектра (56 полос; на
паузе или без данных остаётся «спящая» линия). Треки помечены бейджами
провайдеров (☁ SoundCloud, ♪ YouTube Music) — в очереди, в списках и в
now-playing видно, чей трек играет.

### Мультисессия по умолчанию

С 21.09.2026 выбор «одного источника каталога» перестал быть
обязательным: по умолчанию библиотека, поиск, лайки и лента ходят во
**все подключённые клиенты одновременно** — YouTube Music и SoundCloud
отвечают параллельно, латентность равна самому медленному запросу, а не
сумме. Результаты склеиваются в детерминированном порядке, поэтому
списки не прыгают от запуска к запуску; бейджи ☁/♪ подсказывают, чей
трек. Сфокусироваться на одном клиенте по-прежнему можно: сохранённый
источник каталога (`c` в TUI, `--provider` в CLI) персистится и
сужает каталог до одного провайдера — это фокус-режим, а не
необходимость.

 Вид Clients показывает всех
подключённых провайдеров с реальным статусом: `Connected` или
`Sign in` с подсказкой, как залогиниться. Ниже провайдеров в Clients —
строка `Restart tmusd`: полный перезапуск демона из панели (перечитывает
cookies браузера и библиотеки; очередь и громкость демон персистит сам).
Отказ воспроизведения
(403 по ссылке, битый файл) здесь больше не выглядит как молчаливый
стоп: причина пишется демоном в `PlayerState.last_error` и видна в
нижнем блоке панели. Плеер сам переходит к следующему треку, но не
более 3 раз подряд — на четвёртом останавливается с видимой причиной,
чтобы общий сбой не проматывал всю очередь. Прежние карточки
Current/Up Next удалены — сейчас играет и что дальше видно в очереди
справа.

### Бинды

Экран помощи панели сгруппирован по разделам «Навигация», «Поиск»,
«Плеер и библиотека» и показывает только актуальные бинды из таблицы ниже.

| Клавиши | Действие |
|---|---|
| `Tab`, `ctrl+l`/`ctrl+h` | фокус буферов: центральный список ↔ очередь |
| `ctrl+j`/`ctrl+k` | цикл секций (вперёд/назад) |
| `1`–`5` | секция |
| `j`/`k`, `↑`/`↓` | ход по Y (с автоповтором; в Library — шаг сетки ±4 карточки, в очереди — своя строка) |
| `h`/`l`, `←`/`→` | ход по X (в Library — ±1 карточка; в EQ — ±1 дБ) |
| `Return` | открыть/играть строку; в очереди — играть с позиции (queue-goto); в поиске — искать изменённый запрос и выйти в normal |
| `BackSpace` | назад по иерархии: плейлист → Library, поиск → Home, из очереди — в центральный буфер |
| `Space` | play/pause (в плейлисте и EQ — активировать строку) |
| `g` | прыжок в начало/конец списка |
| `n`/`p` | следующий/предыдущий трек |
| `<`/`>` | громкость ±5 (с автоповтором) |
| `r` | цикл повтора (none → track → queue) |
| `s` | shuffle |
| `f`/`d` | лайк/дизлайк строки курсора (на Home — текущего трека; в очереди — строки очереди) |
| `a` | добавить трек курсора в плейлист (поповер выбора; в Library — создать новый) |
| `D` | удалить: в плейлисте — трек из него, в Library — сам плейлист |
| `ctrl+d` | показать/скрыть дизлайкнутые |
| `/` или `.` | поиск (та же физическая клавиша на ЙЦУКЕН) |
| `i` | insert-режим ввода; выход — `Esc` или быстрые пары `jj`/`jk` (`oo` эскейпом больше не является — обе буквы остаются текстом) |
| `←`/`→`, `Home`/`End`, `Delete` | в вводе — ходить курсором по код-поинтам и стирать символ под/перед кареткой; каретка видима |
| `ctrl+BackSpace` | в вводе — стереть слово слева (readline-модель, без автоповтора) |
| `o` | открыть TUI (панель закрывается) |
| `Esc` | закрыть панель |
| EQ: `j/k`, `h/l`, `Return`, `0` | выбрать полосу, ±дБ, вкл/выкл, сброс в Flat (enabled не трогает) |

Латиница приходит одним аккордом в верхнем регистре, кириллица —
именами кейсимов; таблица снята `xkbcli how-to-type --layout ru`, поэтому
бинды работают без переключения раскладки.

### Home — лента рекомендаций

Центральная колонка Home — компактный хиро играющего трека плюс полки
рекомендаций. По умолчанию лента агрегирует всех подключённых клиентов
(YouTube Music отвечает InnerTube `browse` со страницей `FEmusic_home`),
явный фокус (`--provider`/`c`) сужает её до одного. Лента приходит
страницами: ответ — `{shelves, next}`, где `next` — непрозрачный курсор
демона. Догрузка работает у демона, а не у рендерера: панель, подобравшись
курсором к хвосту загруженного, запрашивает следующую страницу и
сливает её с уже показанной — повторяющиеся полки и карточки
дедуплицируются, списки не прыгают. Артисты и видео из ответа
отбрасываются — играть из панели можно треки и плейлисты, остальное
было бы мёртвым грузом в сетке. Разбор полос-«каруселей» делает
провайдер; наружу — `CatalogShelf` (заголовок, подзаголовок,
элементы). Ход: `j`/`k` — полки, `h`/`l` — карточки внутри полки,
`Return` — играть/открыть (одиночный трек стартует радио по сиду); в
углу — счётчик окна карточек. Пустой
`next` — лента дочитана.

Лента кэшируется в демоне: ключ `tmus.home` живёт 600 секунд и
обновляется через single-flight — параллельные запросы сливаются в один
сетевой заход, а не дёргают InnerTube горсткой. Протухшие полки не
отдаются — честная ошибка лучше несвежих советов. Сервис плагина держит
последнюю удавшуюся ленту у себя (свой TTL 300 с) и в фоне докачивает
обложки в тот же ключ, не трогая тяжёлый snapshot `tmus`. На CLI то же
самое: `tmus home` отдаёт первую страницу, `tmus home-more <cursor>
[--provider P]` — следующую по курсору из ответа.

### Рейтинги

Оценка ставится клавишами `f` (♥, лайк) и `d` (×, дизлайк), повторное
нажатие снимает. Дизлайкнутые треки по умолчанию спрятаны во всех
списках — фильтр локальный, демона панель не дёргает; `ctrl+d`
показывает их снова. Дизлайк играющего трека скипает его (см. «Рейтинги
и плейлисты»). Вид «liked» без фокуса на провайдере — агрегат: локальные
оценки демона и лайки провайдеров склеиваются с дедупликацией по треку.
`f` синхронизирует лайк в сторону провайдера там, где тот умеет
серверные лайки (включая SoundCloud); если провайдер недоступен,
локальная оценка сохраняется, а ошибка видна — интерфейс не разъезжается.

### Спектр

Виджет бара подписан на аудио-мост хоста (`onAudioSpectrum`, полосы
строкой CSV) и пишет их в лёгкий ключ состояния `tmus.spectrum` — не
чаще раза в 125 мс, потому что потолок перерисовки панели — полный draw
8 раз в секунду, чаще писать бессмысленно. В панели у спектра один
потребитель — нижний блок now-playing: 56 полос в его основании, на
паузе или без данных остаётся спящая линия. Сам спектр отдаёт виджет,
рисует noctalia — поэтому `cava` не нужен.

### Плейлисты

`a` на треке открывает поповер выбора: список библиотечных плейлистов и
«+ New playlist…». Существующий — добавляет трек сразу; «New…» — ввод
имени (insert-режим, как поиск), после Enter панель шлёт составное
событие: сервис создаёт плейлист, берёт id из ответа CLI и добавляет
трек в него одной цепочкой — гонки с дубликатами имён исключены.

Новые плейлисты при интерактивном создании — **локальные, у демона**:
они смешивают треки любых провайдеров в одном списке и не зависят от
капризов чужих API. Явный выбор провайдера (`--provider` в CLI)
создаёт нативный плейлист у этого провайдера. Нативные добавление,
удаление трека и удаление плейлиста доступны только там, где провайдер
заявляет соответствующую возможность; плагин и TUI показывают действия
по этим возможностям, а не по догадкам. Переименование (`pl rename`) и
удаление по позиции — только для локальных плейлистов: у трейта
`Catalog` нет rename, а нативное удаление трека (когда оно поддержано)
идёт по идентификатору у провайдера, не по позиции. Локальное удаление
идёт **по позиции** (`pl rm-at`): дубликаты одного трека независимы,
убирается ровно та запись, на которой курсор. `D` в виде плейлиста
убирает трек из него, в Library — удаляет плейлист (без confirm —
операция обратима созданием заново). Локальный плейлист можно
переименовать через `pl rename`. После каждой правки демон шлёт сигнал
`playlists_changed`, сервис перечитывает библиотеку целиком — на 18
плейлистов это дешевле инкрементальных правок.

## TUI

`tmus` без аргументов поднимает TUI. Бинды:

| Клавиши | Действие |
|---|---|
| `q`, `ctrl+c` | выход |
| `Tab` | переключение вкладок |
| `j`/`k`, `↑`/`↓` | курсор |
| `h`/`l`, `←`/`→` | выйти из плейлиста / открыть |
| `Return` | играть выбранное |
| `Space` | play/pause |
| `n`/`p` | следующий/предыдущий |
| `+`/`-` | громкость |
| `s` | shuffle |
| `r` | цикл повтора |
| `f`/`d` | лайк/дизлайк выбранного |
| `a` | добавить выбранное в плейлист (пикер + «+ New playlist…» с inline-вводом имени) |
| `D` | в треках плейлиста — убрать трек, в списке плейлистов — удалить плейлист |
| `ctrl+d` | показать/скрыть дизлайкнутые |
| `c` | фокус источника каталога: цикл «все клиенты → по одному» (по умолчанию библиотека и поиск грузятся у всех подключённых сразу, `c` сужает каталог до одного клиента) |
| `ctrl+r` | перечитать сессии провайдеров (после логина в браузере) |
| `/` | режим поиска; `Esc` — выход из него |

Отказ воспроизведения не оставляет плеер молча остановившимся: причина
видна в `tmus status` (поле `last_error`) и в журнале демона, а плеер
сам уходит к следующему треку (не более 3 неудач подряд — защита от
проматывания очереди при общем сбое).

Активация одиночного трека из поиска в TUI запускает радио по этому
сид-треку (`tmus radio`): очередь — сид плюс рекомендации, у хвоста
дозаполняется; провайдер без радио играет конечный один трек.

## CLI `tmus`

Каждая подкоманда — один запрос к демону и печать результата: подкоманды
вешаются на медиа-клавиши Hyprland и дёргаются плагином noctalia, поэтому
каждая обязана завершаться сама и не трогать терминал. У большинства
есть `--json` — точное зеркало протокола для скриптов.

| Команда | Действие |
|---|---|
| `tmus` | TUI |
| `tmus toggle \| next \| prev \| pause \| stop` | для медиа-клавиш |
| `tmus play [<provider>:<id>]` | играть трек; с id — однотрековый контекст (очередь заменяется), без id — текущий/первый из очереди |
| `tmus play-playlist <id> [--track <provider>:<id>]` | играть плейлист; старт — с сид-трека по стабильному составному id, а не по позиции (состав плейлиста мог поменяться); без `--track` — с начала |
| `tmus play-context <p>:<id>,<p>:<id>,… [--start N]` | играть список как контекст: очередь заменяется целиком, старт с позиции (панель шлёт выдачу поиска/полку) |
| `tmus radio <provider:id>` | радио по сид-треку: очередь заменяется сидом плюс рекомендациями и дозаполняется у хвоста (YTM); провайдер без радио — конечное воспроизведение одного трека |
| `tmus seek +15 \| seek 90` | относительно или абсолютно |
| `tmus vol +5 \| vol 40` | со знаком — от текущей, без — абсолютная (0..100) |
| `tmus loop none\|track\|queue`, `tmus shuffle on\|off\|toggle` | режимы |
| `tmus status` | состояние плеера |
| `tmus queue` | очередь |
| `tmus queue-goto <N>` | прыгнуть на позицию очереди (индекс 0-базный) |
| `tmus home [--provider P] [--json]` | первая страница полок рекомендаций (`FEmusic_home`), ответ `{shelves, next}`; без `--provider` — агрегат всех подключённых, кэш в демоне 600 с + single-flight |
| `tmus home-more <cursor> [--provider P] [--json]` | следующая страница ленты по непрозрачному курсору из ответа `home`; пустой `next` — лента дочитана |
| `tmus library [--provider P]` | библиотека; без `--provider` — агрегат всех подключённых клиентов: локальные плейлисты плюс нативные |
| `tmus library-tracks <playlist_id>` | треки плейлиста |
| `tmus library-tracks-more <playlist_id>` | следующая страница треков от курсора догрузки (пустой ответ — дочитано) |
| `tmus liked [--json]` | лайки; дедуплицированный агрегат локальных оценок демона и лайков всех подключённых клиентов |
| `tmus search <запрос> [--kind all\|tracks\|artists\|playlists] [--provider P]` | поиск; по умолчанию tracks, `all` склеивает три запроса на клиенте |
| `tmus rate <p>:<id> like\|dislike\|none` | оценка (дизлайк играющего скипает) |
| `tmus ratings` | все локальные оценки демона |
| `tmus pl new <имя> [--provider <id>]` | создать приватный плейлист, печатает его id; без `--provider` — **локальный** плейлист демона (можно смешивать треки любых провайдеров); явный `--provider` — нативный у этого провайдера |
| `tmus pl add <pl> <p>:<id>` / `pl rm <pl> <p>:<id>` | добавить/убрать трек (в нативных плейлистах — только если провайдер поддерживает правку состава) |
| `tmus pl rename <pl> <новое имя>` | переименовать плейлист; только локальные — у трейта `Catalog` нет rename, нативное переименование не поддерживается |
| `tmus pl rm-at <pl> <N>` | убрать из плейлиста запись по позиции (0-базная): дубликаты одного трека независимы; только локальные плейлисты |
| `tmus pl del <pl>` | удалить плейлист |
| `tmus pl ls [--json]` | список библиотечных плейлистов |
| `tmus eq` | состояние EQ; `--on`/`--off`/`--preset X`/`--band N:G`/`--json` |
| `tmus cache stats \| pin <id> \| unpin <id> \| gc \| warm <playlist>` | офлайн-кэш |
| `tmus events` | поток событий JSON построчно (им пользуется плагин) |
| `tmus ping` | RTT демона; намеренно НЕ автозапускает демона |
| `tmus stop-daemon` | остановить демон |

Примеры:

```sh
tmus play ytmusic:dQw4w9WgXcQ   # трек по id провайдера
tmus eq --on --preset "Bass Boost"
tmus eq --band 3:-4.5           # третья полоса в −4.5 дБ (полосы 1-базные)
tmus cache warm <playlist-id>   # докачать плейлист в фоне
```

`--band` принимает абсолютное усиление, а не дельту: панель noctalia
считает дельту у себя и шлёт итог, демон принимает только полную десятку —
клиент правит одну полосу из текущего набора.

## Конфиг

`~/.config/tmus/config.toml`. Файла нет — работают значения по умолчанию.

```toml

audio_format = "bestaudio[acodec=opus]/bestaudio"
discord_rpc = true
# Application ID из Discord Developer Portal. Своё приложение
# обязательно: с чужим в профиле было бы чужое имя и чужая иконка.

# Незнакомый ключ демон отвергает с указанием строки, а не проглатывает

[cache]

# Автодетект обычно справляется; путь нужен, когда профилей несколько.
```

Запасной путь — переменная `TMUS_DISCORD_APP_ID`; конфиг важнее её.

## Эквалайзер

10 полос на частотах ISO 32–16000 Гц (`32, 64, 125, 250, 500 Гц, 1, 2,
4, 8, 16 кГц`), усиление каждой — в диапазоне ±15 дБ. Двадцать пресетов:
`Flat, Bass Boost, Vocal Boost, Pop, Rock, Hip-Hop, Jazz, Classical,
Electronic, Acoustic, Deep Bass, Bright, Crisp, Live, Headphones,
Small Speakers, Laptop, Car, Earbuds, Podcast`.

Демон принимает только полную десятку полос; набор, не совпадающий ни с
одним пресетом, показывается как `Custom`. Состояние персистится в
`queue.json` вместе с громкостью — рестарт демона ничего не сбрасывает.
`eq flat` из панели обнуляет полосы, не трогая `enabled`: выключенный
эквалайзер с обнулёнными полосами — ровно то, что ожидает «сброс».

Управление — `tmus eq` (CLI) или вид EQ панели (`j/k` полоса, `h/l`
усиление, `Return` вкл/выкл, `0` — Flat).

## Офлайн-кэш

Играемый трек пишется на диск, следующий в очереди докачивается заранее
(`prefetch_next`). Есть файл — провайдер не опрашивается вовсе.
Вытеснение LRU по лимиту `limit_bytes`, закреплённое (`tmus cache pin`)
не вытесняется никогда. `tmus cache warm <playlist>` докачивает плейлист
целиком в фоне.

База кэша работает с `synchronous=NORMAL` и `busy_timeout`: на каждое
попадание в кэш fsync был дороже самого воспроизведения. LRU-метка
`accessed_at` обновляется не чаще раза в минуту, а не на каждое
использование.

## Рейтинги и плейлисты

Оценки живут у демона и переживают рестарт. Запись оценки локальная:
состояние демона обновляется сразу и сохраняется даже при сбое
провайдера — ошибка зеркалирования в сторону провайдера сообщается,
но локальный лайк не откатывается. Дизлайк
играющего трека скипает его; лайк синхронизируется в сторону провайдера.
Вид «liked» без фокуса — дедуплицированный агрегат локальных оценок
и серверных лайков провайдеров; при сбое провайдера локальное состояние
не теряется.

Кастомные плейлисты по умолчанию локальные (интерактивное создание и
`pl new` без `--provider`) и смешивают треки любых провайдеров. Нативные
плейлисты YouTube Music при удалении требуют `setVideoId` —
внутреннего идентификатора записи, который выдаётся при чтении
плейлиста; без чтения карты `track → setVideoId` сервис не знает,
какую запись убрать.

## Провайдеры

### YouTube Music

Провайдер `tmus-ytmusic`.

- **Каталог** — InnerTube: `search`, `browse`, `next` с cookie-сессией
  браузера и подписью `Authorization: SAPISIDHASH …` (sha1 от
  `SAPISID + пробел + origin + timestamp`). Копировать cookie вручную
  не нужно.
- **Резолв потока** — по умолчанию через `yt-dlp` (см. «Грабли» про
  `player_client` и заголовки — оба штофа уже обойдены). С 21.09.2026
  резолв идёт цепочкой клиентов `web_embedded` → `web_music` → `mweb` по
  URL `www.youtube.com/watch?v=`, каждая ссылка проверяется пробным
  `Range: bytes=0-0`; негодная — повод взять следующего клиента.
  Опционально
  включается `fast_resolve`: прямой player-запрос клиента VISIONOS,
  который не требует JS-плеера и PO-токена и отдаёт прямые
  googlevideo-ссылки по обычной cookie-сессии — цель <1 с против ~5 с.
  Любая ошибка быстрого пути падает в штатный yt-dlp-путь, причина — в
  debug-лог; причина сбоя воспроизведения пишется в журнал и видна в
  `tmus status` (поле `last_error`).
- **Почему фолбэк держим.** VISIONOS не отдаёт «Made for kids»-треки, а
  любая смена защиты на стороне YouTube сломала бы быстрый путь молча.
  yt-dlp чинят за нас; он остаётся медленной, но живучей дорогой.

Инцидент 20.09.2026: YouTube перестал принимать обычные GET по ссылкам
клиента WEB_REMIX (`web_music`) — 403; ссылка проходит только с
ограниченным `Range` ≤1 МиБ. Из-за этого воспроизведение некэшированных
треков упиралось в 403, а фоновая докачка сыпалась. Лечится цепочкой
клиентов с пробой (`web_embedded` первым) и бэкоффом докачки; апстрим —
[yt-dlp#17682](https://github.com/yt-dlp/yt-dlp/issues/17682) и
[yt-dlp#17705](https://github.com/yt-dlp/yt-dlp/issues/17705).

### SoundCloud

Провайдер `tmus-soundcloud`.

- **Каталог** — api-v2 (`api-v2.soundcloud.com`): поиск треков,
  альбомов, плейлистов и артистов, поисковые подсказки (`/search/queries`),
  плейлисты `users/:id/playlists`, лайки `users/:id/likes` и лента
  `/stream` как Home. Все запросы идут с браузерными cookies —
  бот-защита (datadome) без них отвечает капчей на пишущих запросах.
- **Авторизация** — сессия браузера: кука `oauth_token` с домена
  `soundcloud.com`, проверка через `api-auth` `connect/session`. Статус
  виден в TUI и в виде Clients панели; перечитывание — `ctrl+r` в TUI,
  рестарт демона не нужен. Поиск и воспроизведение публичных треков
  работают и без логина. Профиль браузера у SoundCloud свой —
  `browser_profile` в `[providers.soundcloud]` (иначе берётся общий).
- **client_id** — извлекается из JS-ассетов soundcloud.com (как делает
  yt-dlp), есть запасное значение на случай сдвига ассетов;
  переопределение — `client_id` в `[providers.soundcloud]`.
- **Резолв потока** — yt-dlp по URL `https://api.soundcloud.com/tracks/<id>`
  с cookies браузера; селектор пинит прогрессивный MP3 (HLS-манифест в
  офлайн-кэше был бы «скачано, но не играет офлайн»).
- **Лайки** уходят на сервер SoundCloud (`PUT/DELETE
  users/:id/track_likes/:track`), дизлайк остаётся локальным — у
  SoundCloud дизлайков нет. Плейлисты: чтение, создание (приватные,
  JSON-протокол) и удаление — через api-v2; правка состава (добавление
  и удаление треков) нативно **не поддерживается**, если capability
  провайдера не заявляет обратного — вместо этого треки SoundCloud
  кладутся в локальные плейлисты демона, где смешиваются с любыми
  провайдерами.
- **Фильтрация выдачи**: заведомо обрывочные и нестримабельные записи
  (сниппеты) отфильтровываются из поиска и библиотеки, чтобы «трек»
  не падал воспроизведением на ровном месте. Если трек всё же не
  резолвится (DRM, недоступность), при проигрывании списка он
  **автоматически скипается** с ограниченным лимитом подряд —
  чтобы общий сбой не проматывал всю очередь; причина скипа видна
  в терминале как явная ошибка.

## Архитектура

```
tmus (TUI и подкоманды) ─┐
noctalia / MPRIS ────────┼─→ tmusd ─→ mpv (подпроцесс, JSON-IPC)
Discord RPC ─────────────┘     │
иконка в трее ─────────────────┤─→ провайдеры (каталог + резолв потока)
                               └─→ SQLite + офлайн-кэш аудио
```

Workspace:

| Крейт | Ответственность |
|---|---|
| `tmus-core` | модель (`Track`, `TrackId`, `EqState`, …), control-протокол |
| `tmus-provider` | трейты `Account`/`Catalog`/`Resolver` |
| `tmus-ytmusic` | провайдер YouTube Music (InnerTube + yt-dlp) |
| `tmus-soundcloud` | провайдер SoundCloud (api-v2 + yt-dlp) |
| `tmus-player` | обёртка mpv (JSON-IPC) и очередь |
| `tmus-daemon` | демон: сокет, MPRIS, трей, Discord RPC, офлайн-кэш |
| `tmus-tui` | TUI и одноразовые подкоманды `tmus` |

Протокол — newline-delimited JSON поверх unix-сокета, один на всех
потребителей: MPRIS, SNI-трей, Discord RPC, TUI и подкоманды — клиенты
одного `Cmd`-enum; прямого доступа к плееру нет ни у кого. Так добавление
провайдера или фичи не требует новой точки входа, и состояние не
расходится между потребителями. `id = 0` после `subscribe` переводит
соединение в односторонний поток событий.

Приложение построено **вокруг абстракции провайдеров, а не вокруг одного
сервиса**. Три трейта: `Account` (авторизация), `Catalog` (поиск,
библиотека, плейлисты), `Resolver` (`TrackId` → откуда играть).

Причина такого разделения: каталог обобщается чисто, а добыча потока —
нет. YouTube Music и SoundCloud резолвятся через `yt-dlp`; Spotify так
резолвиться не может — там свой протокол. Один трейт на оба дела
заставил бы Spotify притворяться yt-dlp-провайдером.

Сквозное правило: всё знание о YouTube — InnerTube, SAPISIDHASH,
googlevideo — живёт только в `tmus-ytmusic`. Все остальные фичи —
очередь, офлайн-кэш, MPRIS, трей, Discord RPC, TUI, панель — работают
над `Track` и не знают, какой сервис играет. Очередь смешанная: треки
разных провайдеров лежат в ней рядом.

Демон отдельно от интерфейса намеренно: музыка играет с закрытым
терминалом, а иконка в трее остаётся. Закрытие TUI ничего не
останавливает.

## Интеграция с noctalia

Правок в саму noctalia не требуется: демон публикует
`org.mpris.MediaPlayer2.tmus` и иконку `org.kde.StatusNotifierItem`,
которые она читает штатно. Сигналы `PropertiesChanged` коалесцируют:
раньше один `tmus next` давал 40 сигналов (4 раунда × 10 свойств,
замерено `dbus-monitor`), теперь — один с полным набором свойств
(имена совпадают с геттерами интерфейса `...Player`).

Виджет в баре, панель и спектр — отслеживаемый пакет
`packaging/noctalia/tmus`: он устанавливает плагин в локальный каталог
плагинов noctalia. В одной бар-капсуле соседствуют виджет
`q/tmus:tmus-widget` и встроенный в noctalia `audio_visualizer`; спектр
рисует сама noctalia, поэтому `cava` не нужен.

## Медиа-клавиши

Своих глобальных хоткеев плеер не регистрирует, и это не пробел. В
Wayland клиент получает клавиши только с фокусом, а у демона нет окна
вовсе. Клавишу ловит компоновщик — приложению остаётся объявить себя
плеером, что и делает MPRIS. Electron-плееры работают так же: свой
MPRIS им даёт Chromium, а `globalShortcut` у них на Wayland не
регистрируется вообще.

Отсюда два варианта, и разница между ними одна.

**Через MPRIS — ничего настраивать не надо**, если оболочка уже
привязала клавиши к активному плееру (у noctalia это
`noctalia msg media toggle|next|previous`). Минус: когда на шине висит
второй плеер — мессенджер, браузер — «дальше» может уехать туда.

**Напрямую — клавиши всегда управляют музыкой:**

```conf
bindl = , XF86AudioPlay, exec, ~/.cargo/bin/tmus toggle
bindl = , XF86AudioNext, exec, ~/.cargo/bin/tmus next
bindl = , XF86AudioPrev, exec, ~/.cargo/bin/tmus prev
bindl = , XF86AudioStop, exec, ~/.cargo/bin/tmus stop
```

`bindl`, а не `bind` — тогда клавиши работают и на залоченном экране.
Полный путь обязателен: `~/.cargo/bin` в PATH у компоновщика обычно нет,
и короткое `tmus` молча ничего не сделает.

Системную громкость на плеер вешать не стоит: `XF86AudioRaiseVolume`
меняет громкость всего звука, а не одного трека.

## Замеренные грабли

Записаны, потому что каждая выглядит как поломка совсем в другом месте.

- **`player_client` не пинится — резолв идёт цепочкой с пробой.** После
  20.09.2026 клиенты `web_music`, `mweb`, `web_creator` на yt-dlp
  2026.08.19 дают 403, а `tv`/`android`/`ios` — вовсе пустой player
  response; первым в цепочке стал `web_embedded`. Порядок —
  `web_embedded` → `web_music` → `mweb`, каждый клиент зовётся по URL
  `www.youtube.com/watch?v=`, каждая полученная ссылка проверяется
  пробным запросом с `Range: bytes=0-0` (200/206), негодная — повод
  взять следующего клиента. Лучший аудио-формат у `web_embedded` —
  itag 251 (~139k opus) против прежних ~266k у WEB_REMIX.
- **`mpv --http-header-fields` режет значения по запятым.** Заголовок
  `Accept` от `yt-dlp` содержит запятые → googlevideo отвечает `400`,
  тогда как тот же URL в `curl` даёт `206`. Передаётся только
  `User-Agent`.
- **В `property-change` значение лежит в поле `data`**, а не в поле,
  названном по имени свойства. Чтение из `position`/`duration`/`pause`
  давало `None` на каждом кадре — плеер выглядел молчащим при рабочем
  звуке.
- **URL потока живёт около шести часов** (`expire=`). Кэшируются
  метаданные и файлы, URL — никогда.
- **Cookies Chromium на Linux — AES-128-CBC**, а не GCM: ключ
  `PBKDF2-HMAC-SHA1("peanuts", "saltysalt", 1, 16)`, IV — 16 пробелов,
  при `meta.version >= 24` первые 32 байта открытого значения нужно
  отбросить. Часть cookies (`v11`) зашифрована ключом из keyring и не
  читается — они пропускаются, ошибка только если не набралось ни одной.
- **mpv нужно гасить явно и дожидаться смерти.** `quit` по IPC уходит
  асинхронно, и демон успевает выйти раньше записи — mpv остаётся
  сиротой на ~40 МБ и продолжает играть без управления. Вторая сторона
  той же грабли — дубликаты демона: параллельные автозапуски из CLI
  раньше рождали несколько `tmusd`, каждый со своим mpv и филлером,
  и все писали один `queue.json`. Теперь демон берёт эксклюзивный
  замок `<runtime>/tmus.lock`: второй экземпляр при живом демоне
  не стартует — пишет об этом в журнал и выходит, ничего не трогая.
- **mpv-сироты после тестов.** Тесты теперь гасят mpv сами (Drop у
  плеера), а подметальщик `orphan_sweep` остаётся страховкой от
  жёсткой смерти демона.
- **Цена быстрого скипа — целиком в порождённых `yt-dlp`, в `top` по
  `tmusd` её не видно.** Один резолв = 0.9 CPU-с / 4 с wall / 335 МБ RSS,
  скип незакэшированного трека запускал до двух (`--cookies-from-browser`
  заставляет расшифровывать cookie-базу заново). Шторм 8 одновременных
  `tmus next`: пик 676 МБ RSS, 52.8 CPU-с за 25 с (~2.1 ядра), тогда как
  сам демон потратил 0.28 CPU-с. Поэтому в плеере: семафор на один
  одновременный резолв, счётчик генераций команд — более новая команда
  воспроизведения делает устаревший резолв бесполезным, он возвращает
  `Ok(())` не загружая mpv; предзагрузка следующего трека отменяется по
  `JoinHandle::abort` и стартует с задержкой 500 мс — скип, тут же
  отменённый следующим, не запускает `yt-dlp` вообще.
- **`Event::CacheProgress` на каждый chunk 8 КиБ переполнял шину.**
  Замер: 183 события за 0.37 с = 490 ev/s на файле 3 МБ; при буфере шины
  256 подписчики уходили в `Lagged`. Теперь события троттлятся до 2 Гц,
  а брошенная докачка прерывается, когда трек уже не текущий и не
  следующий.
- **TUI выкачивал всю очередь ради двух чисел.** `Cmd::Queue` на 1000
  треков = 339 КиБ JSON, а клиент запрашивал его на каждую смену индекса,
  используя только `len`/`index`. Теперь длину и индекс берёт из самого
  `Event::QueueChanged`, а кадр рисует только на изменение.
- **Поиск по фильтру отдаёт другой рендерер, чем поиск без него.** Под
  фильтром YouTube Music возвращает `musicResponsiveListItemRenderer`
  (artists 2 шт., playlists 20 шт.) и ноль `musicTwoRowItemRenderer`,
  который парсил только artists/playlists — `tmus search --kind
  artists|playlists` возвращал пустоту. Теперь разбираются оба рендерера.
- **Захваченные клавиши не доходят до `ui.input`.** Пока панель открыта,
  она захватывает весь алфавит, и `Enter` до сфокусированного поля не
  доходит — родной submit мёртв (замер 18.09: Enter запускал первый трек
  списка, а не поиск). Поэтому в режиме ввода `onKey` сам копит строку,
  а `ui.input` — витрина.
